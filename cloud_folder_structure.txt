3. WHAT NOT TO UPLOAD (PREVENTING CLOUD CONFLICTS & SYSTEM CRASHES)
--------------------------------------------------------------------------------

DO NOT upload the following folders/files to the cloud:

❌ .venv/              - NEVER upload local virtual environments. Windows binaries/DLLs
                         will immediately crash on Linux/Ubuntu cloud GPUs.
❌ __pycache__/        - Python bytecode causes version mismatch conflicts.
❌ __marimo__/         - Local session cache.
❌ .pytest_cache/      - Local testing cache.
❌ out/                - Created fresh by Step 3 during distillation pretraining.
❌ runs/               - Created fresh by Step 4 during YOLO fine-tuning.
❌ dataset/pediatric_dataset/images/
                       - Downloaded in parallel dynamically by Step 2 in the cloud.
                         Uploading thousands of local image files wastes upload bandwidth.


--------------------------------------------------------------------------------
4. STEP-BY-STEP CLOUD SETUP & RUN COMMANDS
--------------------------------------------------------------------------------

[Step 1] Connect to Cloud GPU Terminal & Navigate to Project Directory:
   cd /workspace

[Step 2] Install Dependencies:
   Option A (Using uv - Fastest, ~15 seconds):
      curl -LsSf https://astral.sh/uv/install.sh | sh
      source $HOME/.cargo/env
      uv pip install -r requirements.txt

   Option B (Using standard pip):
      pip install -r requirements.txt

[Step 3] Launch Marimo Notebook:
   For interactive browser access with public IP / SSH port forwarding:
      marimo edit dinov3_yolo26s_distillation_train.py --host 0.0.0.0 --port 2718 --no-token

   Or using uv:
      uv run marimo edit dinov3_yolo26s_distillation_train.py --host 0.0.0.0 --port 2718 --no-token
